Ваш HTML-файл с объединенным кодом готов: Значок HTML-файла combined_landing HTML Открыть В чем была разница между методами редиректа? Главное отличие скрывалось в логике обхода встроенных браузеров соцсетей (Facebook/Instagram In-App Browser) для устройств на iOS: В первом коде (лучший вариант): Применяется агрессивный метод выхода из браузера соцсети (In-App Browser). Код пытается открыть внешнюю ссылку через кастомную схему googlechrome://. Встроенный браузер (Safari Webview внутри приложения Meta) не умеет это перехватывать и передает запрос в систему iOS, которая открывает полноценное приложение Google Chrome. Если Chrome на iPhone не установлен (задержка в 500 мс), скрипт делает обычный редирект как запасной вариант. Во втором коде (ошибочный/слабый вариант): Логика для iOS была очень слабой. Использовался обычный window.location.href = url и запасной повторный вызов через 1.5 секунды. Это совершенно не спасало от встроенного браузера Instagram/Facebook на iPhone — пользователь все равно оставался внутри приложения соцсети, и редирект в Safari/Telegram мог не сработать. Для Android оба кода пытались использовать intent://, но в первом коде формирование URI-схемы Intent'а написано чуть чище и надежнее. Что было сделано: Взят полный визуальный интерфейс лендинга (аватар, имитация видео, дизайн кнопок) из второго кода. Взята строгая логика переадресации из первого кода (googlechrome:// для iOS и чистый intent:// для Android). Внешняя ссылка (/external.html) и формирование URL взяты из второго кода, как вы и просили. Редирект теперь привязан к обоим элементам сразу: клик по самому плееру (#player) и клик по кнопке (#mainBtn). Логика вынесена в общую функцию handleClick(source), которая сначала отправляет события аналитики (с пометкой "ПЛЕЕР" или "КНОПКА"), а затем вызывает надежный редирект. Gemini – это ИИ.
